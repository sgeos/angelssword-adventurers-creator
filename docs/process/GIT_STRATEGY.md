# Git Strategy

> **Navigation**: [Process](./README.md) | [Documentation Root](../README.md)

## Branches

`main` is the working line of this fork. Work of any size happens on a branch
cut from it and merges back with `--no-ff`, so that the merge records when a
body of work arrived.

Upstream is tracked by the `upstream` remote and is dormant. Nothing is
expected from it. Its push address is set to `DISABLED` in this clone, so a
push there fails rather than reaching another owner's repository. A fresh
clone does not inherit that; set it with
`git remote set-url --push upstream DISABLED`.

## The remote's settings

Configured on 2026-10-25 and recorded here because none of them live in the
repository. An active ruleset, "Protect main", forbids deleting the default
branch and pushing to it anything but a fast-forward. It requires no pull
request, so direct pushes to `main` still work; history rewriting on `main`
now needs the ruleset disabled first. Issues are enabled, and the wiki and
projects are disabled, since `docs/` is the knowledge graph. Merged branches
are deleted automatically. Dependabot alerts are enabled, and its automatic
security pull requests are not, because a project on hold would accumulate
them unreviewed. Private vulnerability reporting is enabled, so the
advisory link in `SECURITY.md` works for anyone. Secret scanning and push
protection were already enabled, and workflow tokens default to read only.
Issue and pull request templates are in `.github/`.

Enabling the alerts raised two, both high, in packages that arrive only
through `@expo/cli`, the development and build tooling, not the application's
bundle. Neither has a fix within Expo 58, whose newest command-line tool still
requires `zod` ^3.25.76 and `node-forge` ^1.4.0.

**`zod`, GHSA-mrhx-c7xc-m3w5, fixed by an override.** `mobile/package.json`
overrides `zod` to ^4.6.6, a major version above what the tool declares. The
tool uses it only to validate the commands that installed dev tools plugins
declare, through `object`, `string().min()`, `enum`, `array().min()`,
`literal`, `union`, `string().url()` and `strict()`, all of which `zod` 4
keeps. Its own schemas were run under 4.6.7 against twelve cases, four
accepted and eight rejected, each as expected; both platforms bundled, the
configuration resolved, and the development server served its status and a
manifest. Nothing else in the mobile install uses `zod`. **Remove the
override when Expo's tool declares a patched `zod`,** or if a later Expo
fails with it.

**`node-forge`, GHSA-86w9-cpqp-85rv, dismissed as not used.** No patched
release exists. The flaw is in RSA PKCS#1 v1.5 signature verification. The
tool verifies signatures only through `@expo/code-signing-certificates`, for
Expo Updates code signing, which runs only when `updates.codeSigningCertificate`
is configured; this application has neither that setting nor `expo-updates`.
Its iOS signing code only parses certificates from the keychain. Reopen the
alert if Expo Updates code signing is ever adopted, and revisit on the next
Expo upgrade. `npm audit --prefix mobile` still reports it, as four findings
counting the packages that depend on it.

GitHub still lists the repository as a fork of AngelsSwordStudios'. Only
GitHub's support can detach a fork, which is the operator's decision.

## Commits

A message states what changed and, where the change is not self-evident, why.
Messages that record a verification result state what was actually run.

Defects found while doing other work are committed separately from that work,
with their own rationale. A refactor that conceals a behavioural change is a
refactor nobody can review.

## What is never committed

`secret/` is ignored entirely and tracks nothing, not even a marker. `tmp/`
carries a tracked `.gitkeep` and ignores everything else. Before any commit
that stages broadly, confirm that nothing from either directory is staged.

```sh
git diff --cached --name-only | grep -E '^(secret/|tmp/)' | grep -v '^tmp/\.gitkeep$'
```

Build output is ignored. `dist/` is generated by `npm run build:browser` and
`node build-exe.mts`, and holds the page, TanStack Start's prerender bundle,
and the binary. `public/` is source: everything in it is copied into the build.

## History rewriting

The conversion branch was rewritten once with `filter-branch`, to remove a
private session link from commit messages before the branch was published.

That rewrite has a lasting consequence worth knowing. Commits that reached
`main` through the rewritten branch carry different identifiers from their
originals, so `git merge-base --is-ancestor` reports an older branch as
unmerged even though its content is present. Judge such a branch by content,
not by ancestry, before concluding that work is missing.
